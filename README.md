# Message Manager

Teams・Slack・Outlook・Gmail の新着を 1 つのウィンドウに 4 分割で表示する、Windows 用のデスクトップウィジェットです（Dart / Flutter 製）。

- Windows にログインすると自動で起動し、デスクトップに貼り付いた状態で表示されます（常に他のウィンドウの下に表示され、タスクバーには出ません）
- フレームごとに最大表示件数と絞り込み条件（送信者、チーム／チャンネル／ラベル）を変更できます
- メッセージをクリックすると該当アプリ（Teams / Slack / Outlook / ブラウザの Gmail）が開きます

## 取得のしくみ

| フレーム | 方式 | 事前準備 |
|---|---|---|
| Teams | PC のクラシック版 Outlook に届く Teams の通知メールを読む（既定）／Windows 通知 | Teams の「不在時のアクティビティに関するメール」を「できるだけ早く」にする |
| Slack | Windows の通知履歴を読み取る | Slack のデスクトップ通知をオンにする |
| Outlook | PC のクラシック版 Outlook から直接読む（既定）／Windows 通知／Microsoft Graph API | なし（クラシック版 Outlook が入っていれば動く） |
| Gmail | Gmail API（読み取り専用） | Google Cloud で OAuth クライアントを作成 |

**Windows 通知方式について**：Windows は、アプリが出した通知を `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db` に保存しています。このファイルはログインしているユーザー本人が読めるので、組織の管理者承認も、Teams・Slack へのアプリ追加も不要です。読み取った通知はアプリ側に蓄積するので、通知センターから消しても表示は残ります。

## 1. ビルドの準備（初回のみ）

1. Flutter SDK（stable）をインストールします。
2. Visual Studio 2022 をインストールし、ワークロード「**C++ によるデスクトップ開発**」を追加します。
3. `flutter doctor` を実行し、Windows 向けのビルドに問題がないことを確認します。

## 2. プロジェクトの生成とビルド

zip を展開して `message_manager` フォルダに移動し、次を実行します。

```powershell
# windows/ フォルダの残りのファイル（CMake 設定・アイコンなど）を生成する
flutter create --platforms=windows --org jp.nk --project-name message_manager .

flutter pub get
flutter run -d windows        # 動作確認
flutter build windows         # 配布用ビルド
```

> **重要**：`flutter create` は既存のファイルを上書きしませんが、念のため確認してください。
> `windows/runner/` の `flutter_window.cpp`・`flutter_window.h`・`main.cpp` の 3 つは改変版です。
> 冒頭のコメントが日本語でなければ上書きされているので、`tools/runner_backup/` から戻してください。

## 3. 常駐させる

1. `build\windows\x64\runner\Release\` フォルダを**フォルダごと**、移動しない場所にコピーします（例：`C:\Users\81809\AppData\Local\MessageManager\`）。
2. コピーした先の `message_manager.exe` を一度だけ起動します。
3. 起動時に、その exe のパスが Windows のスタートアップ（`HKCU\...\Run`）に登録されます。以後はログインするたびに自動で起動します。

- 自動起動をやめたいとき：設定 → 全般 → 「ログイン時に自動で起動する」をオフ
- 二重に起動しても 1 つしか動きません

## 4. 各サービスの準備

### Teams（通知方式）
- Teams の 設定 → 通知とアクティビティ で、通知の表示先を Windows の通知にします（新しい Teams では既定でそうなっています）。
- 表示したいチャンネルで「…」→ チャンネルの通知 → **すべてのアクティビティ** を選びます。
- 絞り込み：フレーム設定の「チーム名・チャンネル名」に、そのチーム名・チャンネル名を入れます（例：`研究室, 一般`）。

### Slack（通知方式）
- Slack の 環境設定 → 通知 で、デスクトップ通知をオンにします。
- 表示したいチャンネルで、チャンネル名 → 通知 → **すべての新規メッセージ** を選びます。
- 絞り込み：フレーム設定の「チャンネル名」に `#general` などを入れます。
- クリックしたときに特定のチャンネルを開きたい場合は、「既定の開き先」に `slack://channel?team=T0000&id=C0000` を入れます（ID はブラウザ版 Slack の URL で確認できます）。

> Teams・Slack とも、**いま開いて見ているチャンネル**には通知が出ないので、そのメッセージは表示されません。
> Windows の「応答不可（集中モード）」がオンでも通知は記録されるので、表示には影響しません。

### Outlook
**通知方式（既定・設定不要）**
- クラシック Outlook：ファイル → オプション → メール →「デスクトップ通知を表示する」をオン。
- 新しい Outlook：設定 → 全般 → 通知 をオン。
- クリックすると Outlook が起動します（メールを個別に開くことはできません）。

**API 方式（より正確。できる場合のみ）**
件名・本文プレビュー・フォルダ・分類で正確に絞り込めて、クリックすると該当メールが直接開きます。大学のテナントでアプリ登録や同意が禁止されている場合は使えないので、その場合は通知方式のままにしてください。

1. [Entra 管理センター](https://entra.microsoft.com) → アプリの登録 → 新規登録
   - サポートされているアカウントの種類：「この組織ディレクトリのみ」
   - リダイレクト URI：空欄のままで構いません
2. 認証 → 詳細設定 →「パブリック クライアント フローを許可する」を **はい** にします。
3. API のアクセス許可 → Microsoft Graph → 委任されたアクセス許可 → `Mail.Read` と `User.Read` を追加します（どちらも通常は管理者の同意が不要です）。
4. 概要ページの「アプリケーション (クライアント) ID」と「ディレクトリ (テナント) ID」をコピーします。
5. Message Manager の 設定 → アカウント連携 → Microsoft に 2 つの ID を入れて「サインイン」を押します。表示されたコードをブラウザで入力します。
   （手順 1 で「この組織ディレクトリのみ」を選んだ場合、テナント欄が `organizations` のままだとサインインできません）
6. 設定 → Outlook → 取得方式 を「Microsoft Graph API」にして保存します。

### Gmail（API 方式）
1. [Google Cloud Console](https://console.cloud.google.com/) で新しいプロジェクトを作成します。
2. 「API とサービス」→ ライブラリ → **Gmail API** を有効にします。
3. 「OAuth 同意画面」（Google Auth Platform）を設定します。
   - 対象：外部
   - テストユーザーに自分の Gmail アドレスを追加
4. 「クライアント」→ クライアントを作成 → 種類「**デスクトップ アプリ**」を選び、クライアント ID とシークレットをコピーします。
5. Message Manager の 設定 → アカウント連携 → Google に入力して「サインイン」を押し、ブラウザで許可します。

> 同意画面が「テスト」状態のままだと、**7 日ごとにサインインが切れます**。
> 自分専用なら「アプリを公開」で本番にすると切れなくなります。未確認アプリの警告は出ますが、自分のアカウントで「続行」すれば使えます。

## 5. 画面と操作

- **上のバー**：ドラッグすると移動します。右端のボタンは左から「今すぐ更新」「貼り付けの切り替え（ピン）」「設定」「終了」です。
- **縁**：ドラッグするとサイズを変えられます。位置とサイズは保存され、次回も同じ場所に出ます。
- **メッセージ**：クリックすると該当アプリで開き、既読になります。左の色付きの点が未読の印です。マウスを乗せたままにすると全文が出ます。
- **各フレームの ✓✓**：そのフレームをすべて既読にします。

## 6. 設定項目

| 場所 | 項目 |
|---|---|
| 全般 | デスクトップに貼り付け／不透明度／自動起動／更新間隔／Outlook(API) をデスクトップ版で開くか |
| 各フレーム | 表示・非表示、表示名、**最大表示件数**、取得方式、**送信者（受信相手）**、**チャンネル／チーム／ラベル／分類**、除外する語、未読のみ、既定の開き先 |
| アカウント連携 | Microsoft（Graph）と Google（Gmail）のサインイン |
| 通知元アプリ | 通知履歴に記録されているアプリ ID の一覧。通知が拾えないときの確認用 |

- 絞り込みの語はカンマ（`,` または `、`）で区切ります。いずれか 1 つを含めば表示されます（大文字・小文字は区別しません）。
- 無効にしたフレームは画面から消え、残りのフレームで画面を分けます。

## 7. 注意点・制限

- `wpndatabase.db` は Windows が内部で使っているファイルで、仕様は公開されていません。将来の Windows 更新で形式が変わると、通知方式が動かなくなる可能性があります。
- 通知方式で拾えるのは、PC が起動していて通知が出たメッセージだけです。PC を切っていた間のメッセージは、次に通知が出るまで表示されません。
- 通知の文面はアプリが決めているので、「誰が・どのチャンネルで」がどこに入るかはアプリのバージョンによって変わります。そのため、絞り込みは通知の全文に対して行っています。
- Win+D（デスクトップの表示）を押すと、貼り付けモードのウィジェットもいったん隠れます。
- サインイン情報（トークン）は `%APPDATA%\jp.nk\message_manager\` の JSON に保存されます。共有 PC では使わないでください。

## ファイル構成

```
lib/
  main.dart                   起動処理（位置の復元・貼り付け・自動起動の登録）
  models/                     メッセージと設定のデータ型
  services/
    hub.dart                  取得元をまとめて定期更新し、絞り込んでフレームへ渡す
    windows_notifications.dart  Windows の通知履歴（wpndatabase.db）を読む
    graph_mail.dart           Outlook（Microsoft Graph、デバイスコード方式でサインイン）
    gmail.dart                Gmail API
    native_window.dart        ウィンドウ操作（C++ 側との通信）
    system.dart               自動起動の登録・外部アプリの起動
    storage.dart              設定・履歴・トークンの保存
  ui/                         画面（4 分割・設定・リサイズ枠）
windows/runner/               枠なし・最背面固定・透明度・多重起動防止（C++）
```

## 予定のウィンドウ（Google カレンダー）

Message Manager を起動すると、予定専用の小さなウィンドウ（同じアプリを `--calendar` 付きで起動したもの）も開きます。Notion カレンダーにつないでいる Google カレンダーの予定を、今日から数日分表示します。

1. Google Cloud Console →「API とサービス」→「ライブラリ」で **Google Calendar API** を有効にします（Gmail と同じプロジェクト）。
2. Message Manager の 設定 →「アカウント連携」→ Google の **再サインイン** を押し、カレンダーの読み取りも許可します。
3. 設定 → 全般 →「おすすめの配置に並べる」を押すと、メッセージが右下、予定が右上に並びます。

- 予定をクリックすると Notion カレンダーが開きます（設定 →「予定」でブラウザの Google カレンダーに変更できます）。
- 進行中の予定は青、次の予定は「次」、終わった予定は薄く表示されます。
- Message Manager の × で終了すると、予定のウィンドウも閉じます。
